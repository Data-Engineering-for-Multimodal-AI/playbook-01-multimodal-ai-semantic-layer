# Changelog

## v1.1.0 (2026-11-26)

Nothing the book shows has changed.

### Added
- `make event ID=...` prints one fused event from the running API (`GET /event/{id}`).
- `make check-data DIR=...` and `make load DIR=...`: check a folder of your own encounters
  (images, notes, vitals in the `data/raw/` layout) and ingest it (`scripts/load_encounters.py`).
  Tests in `tests/test_own_data.py`.
- Three measured experiments: `make try-missing`, `make try-contract`, `make try-scale`
  (`experiments/`).
- README: numbered Run it steps, time tiers, Try this, Use your own data, What you end up with,
  Before production, What it costs.
- CI: runs the Run it steps with checks on their output, the three experiments, the own-data
  tests, and prints the time to first output in a clean devcontainer.
- `make setup`, `make run`, `make serve` and `make clean`. `make run` ingests the sample data and
  prints fused events; `make serve` starts the API. `make smoke` is unchanged.
- `.devcontainer/` so the repo opens in GitHub Codespaces with dependencies installed.
- CI: a weekly scheduled run, a `make run` step, and a job that builds the devcontainer and runs
  `make run` inside it.
- `DATA_SOURCES.md`: the datasets and models this playbook uses, with their licenses and citations.
- `make run` writes `.playbook-done` when it passes (ignored by git). `make card` in the
  organization's `.github` repository reads these files and draws a completion card.

### Changed
- README: "What you'll build" is now "How it works"; "Quick start" is now "Run it the way the
  book does", with its content unchanged. The first-edition note points to it.
- README opening: a title that says what you'll do, three sentences on why, the example and what you'll do, then the data engineering problem and what you'll work with.
- Book page numbers now match the printed book (they were Early Release page numbers).
- README: a header image (light and dark), badges for CI, Python, license and Codespaces, a diagram at
  the top of "How it works", and a footer that links the book, all playbooks, and the previous and
  next playbook.
- README: a Troubleshooting section with three common problems and their fixes.
- Dependencies: security patch releases (certifi 2026.7.22 to 2026.10.18, opentelemetry-api 1.45.1 to
  1.45.2).

## 2026.10.1 (2026-10-27)

Checked against the book (Early Release, pages 21–32).

### Fixed
- The synthetic notes' "Notable findings" contradicted the image labels: the generator's term list
  was not in ChestMNIST label order. The list is fixed, and the 11 notes that list findings now name
  the conditions their image is labelled with (only those words changed). A test checks every note.

### Changed
- README: page numbers.

## 2026.10 (2026-10-12): 2026 maintenance update

The printed version is tagged `first-edition`.

### Fixed
- `pip install -r requirements.txt` works: the file was missing. Added `pyproject.toml`, `uv.lock` and a pinned `requirements.txt` (Python 3.12+).
- `python main.py --ingest` rebuilds the DuckDB manifests instead of appending to them. A fresh clone used to end with 450 curated rows for 50 encounters.
- Reviewer UI (`/reviewer/{id}`) returned HTTP 500 on Starlette 1.x; it now uses the current `TemplateResponse(request, name, context)` call.
- `python main.py --setup` (called by `start.sh` and `demo.py`) is now an alias for `--ingest`.
- `semantic_api.py`: `eval()` replaced by `json.loads`; the vitals CSV path is passed as a SQL parameter.
- A fresh clone no longer fails on import when `data/processed/` or `static/images/` is missing.

### Changed
- `generate_raw_data.py` takes `--seed` (default 42).
- README follows the standard playbook layout. It describes encounter linking (shared ID from file names) and synthetic notes and vitals as the code implements them, and lists data licenses (ChestMNIST: CC BY 4.0).
- `src/ingestion.py` is marked legacy (not used by `main.py`).

### Removed from the tree (all regenerated by `--ingest`, or unused)
- `data/processed/granite_lite.db`, `static/images/*`, `src/__pycache__/*.pyc`
- 50 orphaned `data/processed/enc_*_vitals.csv` files, which nothing read

### Added
- `tests/test_smoke.py` and `make smoke`; GitHub Actions smoke test on Python 3.12 and 3.13.
- `.gitignore`, `.env.example` (no keys needed).
